This pitfall is the union of three things you already own: the S52 construction ladder, the base-first rule, and late binding. Ctor order is base first — so base code runs on a half-built object. If the base ctor calls an overridable method, the derived body runs — see the orange arrow, same color code as the key figure — but the derived fields are not initialized yet. One sentence: during the base constructor, your object is only half built — any method it calls must not depend on parts that do not exist yet. Second quick vote: the radius variant — the half-built object can only offer the default 0.0.
