So why does Java bother with inner classes at all? The book gives three answers, one slide each worth. First, multiple inheritance of implementation: since each inner class independently extends something, one outer class can present several behaviors. Second, closures and callbacks: the inner object carries its outer context with it, which is exactly what a callback needs and what plain methods cannot do. Third, the control framework: a fixed event loop, and applications contribute behavior as Event subclasses — often anonymous ones. Hold that picture; it returns as the Swing event model in chapter twenty-two.
