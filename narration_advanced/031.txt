The hierarchy explains the two families in one picture. Throwable splits into Error — JVM disasters like OutOfMemoryError that you should not attempt to catch — and Exception. Most Exceptions are checked: the compiler forces every caller to handle them or declare them upward, which is why file code is full of try-catch. The RuntimeException branch is deliberately exempt: null dereferences, bad indexes, bad casts are programming bugs, not foreseeable conditions — checking them everywhere would drown every method. They fly to the top and crash loudly, which is the correct treatment for bugs.
