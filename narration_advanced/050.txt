Here is the machinery. When the JVM first actively uses a class — creating an instance, touching a static — it loads the bytecode and builds exactly one Class object for it: the fingerprint plus the method table. Every instance secretly points at it, which is how getClass always reports the true runtime type, never the reference type. Three doors lead to the same object: forName by string, which forces loading — that is how plugins get loaded; the class literal, which is compile-time checked; and getClass from an instance. Same Class, three entrances — and the differences are exactly the exam question.
