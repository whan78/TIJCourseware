Two type tests that look interchangeable and are not. instanceof asks the useful question — can this object be treated as a Circle — and answers true for every subclass too, so the test-then-cast idiom is safe. getClass equality asks the pedantic question — is the runtime type exactly this class — and a fancyCircle fails it. Both answers have legitimate uses; mixing them up produces either surprising inclusions or surprising exclusions. And remember: the cast itself is unchecked at compile time — a wrong one throws ClassCastException at run time, which is why the instanceof guard comes first.
