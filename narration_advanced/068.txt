The forbidden four, arranged with their escapes. No new T and no T arrays — because the erased code has no idea what to construct; the workaround is dependency injection, chapter-nine style: hand in a factory or the Class object and let IT create. No instanceof T and no T class literal — the Class object is again the stand-in, via isInstance. No T in catch clauses and no static T fields, because generics belong to instances while statics belong to the one erased class. The ClassTypeCapture idiom at the bottom is worth memorizing — it appears whenever libraries need runtime type identity from generic code.
