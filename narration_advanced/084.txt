Tree containers pay logarithmic insert and lookup to keep elements sorted at every moment. The first set uses natural string order — capital letters sort before lowercase, which is why one lands last; knowing unicode order is itself exam material. The second set carries a composed comparator: length first, then natural order — note the ordering belongs to the container, not to individual calls. The TreeMap one-liner shows the everyday payoff: keys always iterate in order, and range views like headMap come free. Choose trees when sorted output is a requirement, hashed maps when only lookup speed matters.
