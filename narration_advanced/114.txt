The conceptual close-out. An annotation is inert data glued to a declaration; nothing happens until a consumer acts. Three consumers matter: the compiler, which checks targets and override correctness; build-time processors, which generate code from them; and run-time reflection, the framework path. The bottom code makes the inertness concrete — the same method is ordinary Java until TestRunner looks. That is why reading a framework-heavy codebase means following the annotations to their processors. Lab for this chapter is small: build the TestRunner, then add a @VeryImportant marker and filter on it.
