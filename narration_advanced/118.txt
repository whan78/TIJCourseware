The primitive. A thread is a second call stack walking through the same heap as main — that single sentence contains the power and the danger. Define work as a Runnable — a lambda here — hand it to a Thread, and call start, not run: start asks the JVM to create the new stack and invoke run on it, while calling run directly is an ordinary method call on the current thread, the classic beginner bug. Scheduling is the operating system's business; the only timing guarantee is none. Hold the duality — shared heap, separate stacks — because the race condition in a few slides is its direct consequence.
