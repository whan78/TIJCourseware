The subtlest slide of the chapter, so we go slow. Compilers and cores cache variables; thread A may spin on a register copy while thread B updates main memory — A never sees the change. Volatile removes the caching: writes land in memory, reads come from it. But — and this is the exam — visibility is not atomicity: our three-step increment still loses updates even with volatile, because the read-add-write between threads is still unguarded. The two real fixes are synchronized or the atomic classes. If a quiz option says 'volatile makes count++ safe', that option is false. Always.
